### 1.2 Session Storage Hierarchy, Format & Records

#### Filesystem Layout
Claude Code organizes session persistence strictly by project workspace directory within `~/.claude/`:

```text
~/.claude/
├── config.json                               # Global CLI settings & telemetry preferences
├── settings.json                              # Permitted tools, models, environment variables
├── sessions/                                  # Active session process tracking & IPC keys
│   ├── <pid>.json                             # Active session descriptor (sessionId, cwd, socket)
│   └── <pid>.<token_hash>.key                 # UDS peerToken authentication key
├── projects/
│   └── <encoded-project-path>/               # E.g. -Users-daliys-Daliys-Projects-Shardrail
│       ├── <session-uuid>.jsonl               # Primary session append-only transcript
│       └── <session-uuid>/                    # Session auxiliary directory
│           ├── custom-title.json              # Custom session title metadata
│           ├── tool-results/                  # Cached tool execution output blobs
│           │   └── <hash>.bin
│           └── subagents/                     # Sidechain / subagent transcripts
│               ├── agent-<subagent-id>.jsonl
│               └── agent-<subagent-id>/
```

#### Project Path Encoding
The project directory slug is deterministically constructed by replacing directory separators `/` with dashes `-`.
For example:
- Host path: `/Users/daliys/Daliys/Projects/Shardrail`
- Encoded slug: `-Users-daliys-Daliys-Projects-Shardrail`
- Session folder: `~/.claude/projects/-Users-daliys-Daliys-Projects-Shardrail/`

#### Transcript Format & Record Schema
Every session file (`<session-uuid>.jsonl`) is an append-only newline-delimited JSON stream. Each line represents an individual event or turn record.
Key fields present on records:
```json
{
  "parentUuid": "00000000-0000-0000-0000-000000000000",
  "uuid": "88cb28db-7e9b-466c-bb9e-49b49a2ee59e",
  "type": "user",
  "message": {
    "role": "user",
    "content": "Review the test suite status"
  },
  "sessionId": "7786ea96-d503-4cb8-96d6-4fdaab9625f5",
  "timestamp": "2026-11-01T21:06:15.991Z",
  "cwd": "/Users/daliys/Daliys/Projects/Shardrail",
  "gitBranch": "HEAD",
  "entrypoint": "claude-desktop"
}
```

#### Discovered Record Types (Empirical Audit across 139,363 records)
Scanning all 173 sessions on the host revealed the following distinct `type` values:

1. `user` (43,267 records):
   - User prompt submissions, injected messages, or tool execution return blocks.
   - `message.role`: `"user"`.
   - `message.content`: Plain text string or an array of blocks (`{ type: "text", text: "..." }`, `{ type: "tool_result", tool_use_id: "...", content: "..." }`).
2. `assistant` (85,739 records):
   - Model responses containing structured content blocks:
     - `text`: Assistant natural language responses.
     - `thinking`: Extended thinking / chain-of-thought blocks (`{ type: "thinking", thinking: "...", signature: "..." }`). Unlike Codex, thinking is stored in plain text (unencrypted locally) with an Anthropic cryptographic signature.
     - `tool_use`: Tool invocation requests (`{ type: "tool_use", id: "toolu_01...", name: "Bash" | "Read" | "Edit" | "Glob", input: { ... } }`).
3. `progress` (9,566 records):
   - Intermediate runtime state, background bash execution heartbeats, MCP server initialization, or hook execution traces.
   - Fields: `data: { type: "hook_progress" | "bash_progress" | "mcp_status", ... }`.
4. `system` (572 records):
   - System-level notices, permission denials (`subtype: "permission_denied"`), environment warnings, or token limit warnings.
5. `summary` (219 records):
   - Conversation compaction records. When context window compaction triggers, Claude Code appends a `summary` record containing:
     - `summary`: Compressed narrative summary of compacted turns.
     - `compacted_turn_ids`: Array of turn UUIDs compressed into this record.
     - `leafUuid`: The parent UUID anchor where active uncompacted history resumes.
6. `custom-title` (optional record or stored in `<session-uuid>/custom-title.json`):
   - Custom session title set by the user or auto-generated by the model (`{ "title": "...", "sessionId": "..." }`).
7. `tag` (optional record):
   - User or workspace categorization tags.

#### Subagent & Sidechain Transcripts
- **Location**: Nested inside `<session-uuid>/subagents/agent-<subagent-id>.jsonl`.
- **Identification**: Each record in the subagent transcript contains `"isSidechain": true`, linking back to the parent session via `sessionId` and `parentUuid`.
- **Lifecycle**: Subagents are spawned via tool calls (e.g. `Agent` / `SubagentStart`) and execute in their own isolated turn loops, persisting tool calls and results independently without polluting the main session line sequence.

#### Format Stability Across Versions
- Analyzed records produced across versions `2.1.38` up through `2.1.316`.
- The JSONL record envelope (`parentUuid`, `uuid`, `type`, `sessionId`, `timestamp`) has remained strictly backward compatible.
- Content blocks follow Anthropic's Messages API standard (`text`, `thinking`, `tool_use`, `tool_result`).
- Transcripts are **never compressed with Zstandard** on disk; they remain readable plaintext JSONL, eliminating the need for streaming decompression pipelines.

### 1.3 Programmatic Interfaces

#### 1. `@anthropic-ai/claude-agent-sdk` (TypeScript SDK)
- **Status**: **Officially Supported** by Anthropic (published package `@anthropic-ai/claude-agent-sdk` on npm).
- **Core Operations Exposed**:
  - `listSessions({ dir? })`: Discovers all sessions for a given directory or across all projects on the host. Returns `sessionId`, `summary`, `cwd`, `lastModified`, `fileSize`, `customTitle`, `firstPrompt`, `gitBranch`, `createdAt`.
  - `getSessionInfo(sessionId, { dir? })`: Retrieves metadata for a specific session.
  - `getSessionMessages(sessionId, { dir? })`: Reads and parses the full sequence of messages/turns for a session.
  - `listSubagents(sessionId, { dir? })`: Scans `<session-uuid>/subagents/` to enumerate sidechain subagents.
  - `getSubagentMessages(sessionId, agentId, { dir? })`: Reads subagent turn logs.
  - `renameSession(sessionId, title, { dir? })`: Updates session title.
  - `forkSession(sessionId, { dir? })`: Branches a new session from an existing one.
  - `deleteSession(sessionId, { dir? })`: Deletes session file and auxiliary directories.
  - `query({ prompt, resume?, cwd?, permissionMode?, canUseTool? })`: Executes programmatic agent turns.
- **Under the Hood**:
  - For reading (`listSessions`, `getSessionMessages`): The SDK performs direct filesystem reads from `~/.claude/projects/`. It requires no running daemon or subprocess.
  - For execution (`query`): The SDK spawns the native Claude Code executable (`claude`) as a subprocess with:
    ```bash
    claude --input-format stream-json --output-format stream-json --verbose --permission-prompt-tool=stdio
    ```
    and communicates via JSON Lines over `stdin` and `stdout`.

#### 2. Headless CLI (`claude -p` with `stream-json`)
- **Status**: **Officially Supported** core engine protocol.
- **Flags**:
  - `-p, --print`: Non-interactive headless invocation.
  - `--resume <session-id>`: Resumes a specific session by UUID or title.
  - `--input-format stream-json`: Instructs the CLI to read streaming JSON turn commands and control responses from standard input.
  - `--output-format stream-json`: Emits newline-delimited JSON events for every message chunk, tool call, progress update, and control request.
  - `--permission-prompt-tool=stdio`: Routes dangerous action approvals over stdin/stdout via bidirectional control frames.
  - `--verbose`: Emits full structured metadata on turns.
  - `--fork-session`: Resumes an existing session into a new branched session ID.

#### 3. Hooks Architecture
- **Status**: **Officially Supported** runtime extension mechanism.
- **Discovered Hook Events** (33 distinct event points in `HookEvent`):
  - Session lifecycle: `SessionStart`, `SessionEnd`, `Setup`
  - Turn & Prompt: `UserPromptSubmit`, `UserPromptExpansion`, `MessageDisplay`
  - Tool execution: `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`
  - Permissions: `PermissionRequest`, `PermissionDenied`
  - Compaction: `PreCompact`, `PostCompact`
  - Model switching: `PreModelSwitch`, `PostModelSwitch`
  - Subagents & Collaboration: `SubagentStart`, `SubagentStop`, `TeammateIdle`, `TaskCreated`, `TaskCompleted`
  - Workspace: `CwdChanged`, `FileChanged`, `DirectoryAdded`, `WorktreeCreate`, `WorktreeRemove`
- **What Hooks CAN Do**:
  - Intercept actions before execution (`PreToolUse`) and approve, deny, or modify tool arguments.
  - Inject system context (`systemMessage`) or contextual hints (`additionalContext`).
  - Abort execution cleanly by returning `continue: false` or setting `stopReason`.
  - Block prompt submissions (`decision: 'block'`).
- **What Hooks CANNOT Do**:
  - Cannot initiate new asynchronous conversation turns while the agent is idle.
  - Cannot bypass fail-closed permission denial defaults.
  - Must complete within synchronous timeouts (hook operations run on tight latency budgets).

### 1.4 Terms of Use & Authentication

#### Official Policy Analysis (Anthropic Commercial & Consumer Terms)
1. **Multi-Tenant / Reselling Prohibitions**:
   - Anthropic's terms explicitly forbid SaaS or multi-tenant services from reselling consumer subscriptions (Free, Pro, Max) or proxying requests on behalf of other third-party users.
   - Applications serving multiple users must authenticate using Anthropic Console API keys or cloud provider credentials (AWS Bedrock, GCP Vertex AI).
2. **Owner's Single-User Environment (Shardrail Context)**:
   - Shardrail is a private, self-hosted management control panel deployed on the owner's own hardware (`shardraild` daemon on each machine).
   - The owner controls their own instances and interacts only with their own active development projects.
3. **Supported Authentication Methods in Claude Code**:
   - `claude auth login --claudeai` (Default): OAuth token tied to the user's Claude Pro, Max, or Team subscription.
   - `claude auth login --console` / `ANTHROPIC_API_KEY`: API key billing via Anthropic Console.
   - `claude setup-token`: Generates a long-lived OAuth authentication token for unattended or headless environments (requires Claude subscription).
4. **Architectural Recommendation for Shardrail**:
   - For interactive CLI parity on local machines: `shardraild` can execute headless commands using the owner's existing authenticated local profile (either CLI OAuth session or long-lived token from `claude setup-token`).
   - For automated background runs or high-throughput batching: Anthropic explicitly recommends Console API keys (`ANTHROPIC_API_KEY`) to prevent subscription rate limit flags.
   - Shardrail should allow the owner to configure `ANTHROPIC_API_KEY` optionally in `config.yaml` or inherit existing machine authentication transparently.

### 1.5 Interactive Process Communication & Hooks

#### Discovered Live Process IPC Protocol
Claude Code features an internal Unix Domain Socket (UDS) messaging bus enabling cross-session message routing into already running processes:

1. **Active Process Discovery**:
   - Every running interactive Claude Code session writes a registration descriptor to `~/.claude/sessions/<pid>.json`.
   - The descriptor contains:
     ```json
     {
       "pid": 63915,
       "sessionId": "7786ea96-d503-4cb8-96d6-4fdaab9625f5",
       "cwd": "/Users/daliys/Daliys/Projects/Shardrail",
       "entrypoint": "claude-desktop",
       "messagingSocketPath": "/tmp/cc-socks/63915.sock"
     }
     ```
2. **Authentication Key**:
   - Alongside `<pid>.json`, Claude Code creates `~/.claude/sessions/<pid>.<token_hash>.key` (mode `0600`).
   - Contents:
     ```json
     {
       "peerToken": "3599a071ef28ba6b9de2ddb501d2d3a3",
       "procStart": "2026-11-01T21:06:14.364Z",
       "pidDomain": "darwin"
     }
     ```
3. **Socket Handshake & Wire Protocol**:
   - Connect to `/tmp/cc-socks/<pid>.sock` over Unix Domain Socket.
   - **Line 1 (Auth frame)**:
     ```json
     {"token": "<peerToken>"}
     ```
   - **Line 2 (Message frame)**:
     ```json
     {
       "type": "user",
       "session_id": "7786ea96-d503-4cb8-96d6-4fdaab9625f5",
       "message": {
         "content": "Message text from external client"
       },
       "priority": "next",
       "from": "shardrail",
       "uuid": "<optional-uuid>"
     }
     ```
4. **Behavior Inside Running Session**:
   - If the active session is idle, the message is routed directly to `fe.enqueue({mode: "prompt", ...})`, triggering a new turn.
   - If a turn is actively running, the message is queued for the subsequent turn (`priority: "next"`).
   - If the session is in permission or plan mode, the incoming external message is held until the local user accepts it.
   - If `session_id` does not match the active session, the socket returns an error and rejects the frame.

### 1.7 Permissions & Approvals Architecture

#### How Approvals Work
- **Interactive CLI**: Prompts the user on TTY with options `Allow once`, `Allow always`, `Deny`.
- **Headless Mode (`claude -p`)**:
  - Without approval flags: Any tool call requiring user confirmation is **immediately denied** (fail-closed default).
  - With `--permission-prompt-tool=stdio`: Claude Code routes permission requests over stdout as structured control frames:
    ```json
    {
      "type": "control_request",
      "request_id": "req_01Abc...",
      "request": {
        "subtype": "can_use_tool",
        "tool_name": "Bash",
        "input": { "command": "cargo test" },
        "permission_suggestions": ["allow_command_prefix"],
        "decision_reason": "Executing a shell command requires approval",
        "tool_use_id": "toolu_01Xyz...",
        "requires_user_interaction": true,
        "default_to_no": true
      }
    }
    ```
- **External Response Protocol**:
  - The external client (Shardrail) responds on stdin:
    ```json
    {
      "type": "control_response",
      "response": {
        "subtype": "success",
        "request_id": "req_01Abc...",
        "response": {
          "behavior": "allow",
          "toolUseID": "toolu_01Xyz..."
        }
      }
    }
    ```
  - Or to deny:
    ```json
    {
      "type": "control_response",
      "response": {
        "subtype": "success",
        "request_id": "req_01Abc...",
        "response": {
          "behavior": "deny",
          "message": "User denied tool execution"
        }
      }
    }
    ```
- **Safety Settings That MUST Be Pinned**:
  1. `permissionMode: "default"`: Never use `bypassPermissions` or pass `--allow-dangerously-skip-permissions`.
  2. `--permission-prompt-tool=stdio`: Force all interactive confirmations through the structured stdio control channel.
  3. Fail-Closed on Disconnect/Timeout: If the relay, UI, or socket connection drops, or if no decision arrives before timeout, Shardrail must automatically send `behavior: "deny"` or terminate the turn.
  4. Journal Intent Before Dispatch: Intent must be recorded in the local append-only journal before sending an `allow` response.

### 1.8 Active Session Detection, Locks & Concurrent Resume

#### Active Session Detection
Shardrail can determine whether a session is currently running via:
1. **Session Registry Check**:
   - Inspect files in `~/.claude/sessions/*.json`.
   - Parse each file: if `data.sessionId == targetSessionId`:
     - Check if process `data.pid` is alive via `kill(pid, 0)`.
     - If alive: **Session is actively running in CLI or Desktop**.
     - If dead (stale file from unclean shutdown): Treat as idle.
2. **UDS Socket Probe**:
   - Test connection to `messagingSocketPath` (`/tmp/cc-socks/<pid>.sock`).

#### Locking Behavior & What Happens on Second Process Resume
- **Absence of File-Level Lock**: Unlike Codex (which creates `flock` locks in `~/.codex/thread-writer-locks/`), Claude Code does **not** take POSIX advisory locks on `<session-uuid>.jsonl`.
- **Concurrent Writer Conflict**:
  - If a second process runs `claude --resume <session-id>` while Process A is writing:
    - Both processes will append lines to the same `<session-uuid>.jsonl` file.
    - Because each line has `parentUuid` and `uuid`, the JSONL structure diverges into a tree/fork with multiple heads instead of a linear turn sequence.
    - Turn indices and conversation summaries become inconsistent.
- **Claude Code Mitigation (`--fork-session`)**:
  - Claude Code CLI provides `--fork-session`. When resumed with `--fork-session`, it duplicates the history up to the current turn into a new UUID, ensuring the original session transcript remains pristine.
- **Shardrail Policy for Concurrent Writers (T4.7 / T3.4 Parity)**:
  - If `~/.claude/sessions/<pid>.json` indicates the session is active:
    - Default action: Display `"Active in CLI/Desktop"` indicator in the UI.
    - If user sends a message: Route via UDS `/tmp/cc-socks/<pid>.sock` directly to the live process prompt queue, OR
    - If user requests independent continuation: Resume with `--fork-session` to prevent transcript branching conflicts.

### 2.2 Detailed Comparison: Claude Code vs Codex Architecture

| Architectural Dimension | OpenAI Codex | Anthropic Claude Code |
|---|---|---|
| **Core Process Daemon** | Dedicated `codex app-server` daemon speaking JSON-RPC 2.0 over stdio/UDS/WS. | No standalone daemon; executable CLI (`claude`) run per-invocation or wrapped via Agent SDK. |
| **Storage Hierarchy** | Centralized date-partitioned `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` + SQLite databases (`state_5.sqlite`, `thread_history_1.sqlite`). | Project-partitioned `~/.claude/projects/<slug>/<sessionId>.jsonl` + auxiliary session directory. |
| **Compression at Rest** | Older rollouts automatically compressed with Zstandard (`.jsonl.zst`). | No compression; all sessions remain uncompressed JSONL. |
| **Turn Content Model** | Item-oriented: `response_item` with discriminator `type: message \| reasoning \| function_call \| custom_tool_call`. | Block-oriented: Anthropic Messages API (`text`, `thinking`, `tool_use`, `tool_result`). |
| **Reasoning / Thinking Visibility**| `encrypted_content` blob encrypted by OpenAI API; raw thinking inaccessible locally. | `thinking` block stored in plaintext JSONL with Anthropic signature; full thought process visible! |
| **Subagents** | Inline agent messages or separate rollout files indexed in SQLite. | Dedicated directory `<sessionId>/subagents/agent-<id>.jsonl` with `isSidechain: true`. |
| **Concurrency & Locks** | POSIX advisory file locks (`flock`) on dedicated lock files `~/.codex/thread-writer-locks/<id>.lock`. | Process registry files in `~/.claude/sessions/<pid>.json`; no file-level `flock` on transcripts. |
| **Mid-Turn Steering** | Explicit JSON-RPC method `turn/steer` redirects model mid-turn. | No mid-turn steering RPC; messages queue for next turn. |
| **Injection into Interactive Process**| Not supported for interactive CLI TUI. | Supported via Unix Domain Socket (`/tmp/cc-socks/<pid>.sock`) with peerToken auth. |
| **Approvals Protocol** | Server RPC requests (`item/commandExecution/requestApproval`, etc.). | Stdio bidirectional control frames (`type: "control_request"`, subtype `can_use_tool`). |

### 2.3 Evaluation Against T2.2 `AgentAdapter` Interface

The normalized interface designed in `Shardrail_Core/crates/protocol/src/lib.rs` and implemented in `crates/session-core/src/adapter.rs` maps to Claude Code as follows:

1. **`capabilities() -> AdapterCapabilities`**:
   - `can_list_sessions`: `true` (Direct filesystem scan of `~/.claude/projects/`).
   - `can_read_history`: `true` (Stream `<session-uuid>.jsonl`).
   - `can_stream_events`: `true` (Tailing active file for passive sessions; stdio `stream-json` for active sessions).
   - `can_send_message`: `true` (Spawn `claude -p stream-json --resume <id>` or UDS socket).
   - `can_interrupt`: `true` (`SIGINT` on subprocess).
   - **`can_steer`**: **`false`** (Claude Code does not support mid-turn steering; turns run to completion or interrupt).
   - `can_request_approvals`: `true` (Bidirectional `control_request` stdio channel).
   - `can_change_model`: `false` (Model is set at session launch via `--model`, cannot change dynamically mid-process without restart).
2. **`list_sessions(&SessionListFilter)`**:
   - Maps directly. `~/.claude/projects/` provides directory filter, modified timestamps, and session summaries from `custom-title.json` or initial user turn.
3. **`read_history(&SessionHistoryQuery)`**:
   - Maps directly. Claude Code JSONL lines map to `NormalizedTurn`:
     - User turns -> `NormalizedItem::Message { role: MessageRole::User }` and `NormalizedItem::ToolResult`.
     - Assistant turns -> `NormalizedItem::Message { role: MessageRole::Assistant }`, `NormalizedItem::Reasoning` (from `thinking` blocks), and `NormalizedItem::ToolCall` (from `tool_use` blocks).
     - Compaction records -> `NormalizedItem::SystemNotice` or compaction marker.
4. **`send_message(&str, &str)`**:
   - Maps cleanly. If session is idle: execute headless `claude -p --input-format stream-json --output-format stream-json --resume <sessionId>`.
   - If session is active in another process: send via UDS socket `/tmp/cc-socks/<pid>.sock` or return `SessionLocked` based on policy.
5. **`interrupt(&str, Option<&str>)`**:
   - Maps cleanly. Dispatches `SIGINT` to child process PID.
6. **`resolve_approval(&str, Uuid, ApprovalDecision)`**:
   - Maps cleanly. Writes `{ type: "control_response", response: { subtype: "success", request_id: ..., response: { behavior: "allow" | "deny" } } }` to stdin.
7. **`session_state(&str)`**:
   - Maps cleanly. Checks `~/.claude/sessions/<pid>.json` to return `SessionStatus::Active`, `Idle`, or `LockedElsewhere`.

## 3. Open Risks & Mitigations

1. **Risk: Interleaved Transcript Corruption on Concurrent Resume**:
   - *Detail*: Because Claude Code does not use file-level `flock`, two processes resuming the same session simultaneously append conflicting lines to `<sessionId>.jsonl`.
   - *Mitigation*: Strictly enforce `~/.claude/sessions/<pid>.json` checking before spawning a writer, defaulting to UDS socket routing or `--fork-session`.
2. **Risk: UDS Socket Protocol Changes**:
   - *Detail*: `/tmp/cc-socks/<pid>.sock` is an internal Claude Code mechanism and could evolve in minor releases.
   - *Mitigation*: Treat UDS socket message injection as an enhancement; standard resume via `--resume` or `--fork-session` remains the primary, rock-solid write path.
3. **Risk: Rate Limiting on Subscription Tokens**:
   - *Detail*: Intensive automated turns on Claude Pro/Max subscriptions can encounter rate limits.
   - *Mitigation*: Support `ANTHROPIC_API_KEY` configuration in `config.yaml` as an official alternative to subscription OAuth tokens.
4. **Risk: Large Session History Memory Usage**:
   - *Detail*: Sessions with hundreds of tool outputs can exceed 20 MB JSONL.
   - *Mitigation*: Implement cursor-based reverse streaming in `read_history` so only requested pages are parsed into memory.
