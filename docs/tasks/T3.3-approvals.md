## 1. Research & Context
- **Official Documentation**: Codex app-server JSON-RPC approval notifications (`item/commandExecution/requestApproval`, `item/fileChange/requestApproval`).
- **Installed Codex Version**: Codex `0.166.0`.
- **Established Facts**:
  - Approvals in `shardraild` require write-ahead journaling of intent (`coordinator.respond_approval`) BEFORE delivering any resolution command to the provider.
  - Fail-closed security rule: any timeout, client disconnect, journal commit failure, or provider communication disruption must deny/cancel the request; it must NEVER default to accepting.
  - Option classes are strictly partitioned (`Once`, `Widening`, `BoundaryBreaking`), and limited clients or untrusted scopes are forbidden from resolving widening/boundary options.
  - Web UI renders pending approval cards with disclosed actions (diff, command, paths, context), explicit "Deny" and "Allow once" controls, and blocks responses when disconnected or when checks fail.

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - Daemon socket routing & binding: `approval.respond` command validated against `ApprovalBinding` (`approval_id`, `session_id`, `turn_id`, `provider_request_id`, `content_hash`, `journal_epoch`).
  - Write-ahead journaling: `coordinator.respond_approval` writes `approval_responding` and `approval_responded_unacked` to journal before notifying provider.
  - Fail-closed timeouts & disconnects: `expire_approval` cancels pending approvals via provider and coordinator; client disconnect or provider drop triggers cancellation.
  - Web UI presentation: `SessionArea.tsx` renders approval cards with `state`, `disclosedAction`, `approval-actions` (Deny / Allow once), and offline indicators.
- **Acceptance Criteria**:
  - [x] Show confirmation requests for command execution and file changes.
  - [x] Enforce decisions allow-once/deny; deny by default on timeout, disconnect, and journal error.
  - [x] Write intent to the journal before answering the provider.
  - [x] Failure and fault scenarios verified by automated integration tests.
