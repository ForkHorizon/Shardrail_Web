- **Agent / Tooling Versions**:
  - Codex CLI: `0.166.0`
  - Claude Code CLI: `2.1.38`
  - Rust: `rustc 1.99.0`
  - Node.js: `v22.14.0`, npm `10.9.2`
- **Established Facts**:
  - Codex represents agent executions as turns containing items (`message`, `reasoning`, `function_call`, `custom_tool_call`).
  - Claude Code stores sessions as JSONL events containing content blocks (`text`, `thinking`, `tool_use`, `tool_result`).
  - Neither system natively knows about the other's internal primitives.
  - A normalized domain layer must capture:
    - Session discovery & metadata (working directory, model, git branch/sha, token usage, status).
    - Bi-directional cursor-based turn pagination.
    - Event streaming (turn started, turn progress, item appended/updated, turn completed, status changes).
    - Approval request and resolution lifecycle (allow/deny).
    - Asynchronous message dispatch, interruption, and steering.
    - Explicit capability flags (`AdapterCapabilities`) so UI and clients dynamically query what features each agent backend supports without guessing or hardcoding vendor branching.
- **Invariants**:
  - Zero vendor leakage into the core shared protocol contracts (`shardrail-protocol`).
  - Single source of truth: Rust definitions in `crates/protocol/src/lib.rs` -> JSON Schema (`schema/contracts.schema.json`) -> TypeScript interfaces (`packages/contracts/src/generated.ts`).
  - Schema drift check (`./scripts/check-schema-drift.sh`) strictly enforced.

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - Define normalized data structures in `shardrail-protocol`:
    - `AdapterCapabilities`: `can_list_sessions`, `can_read_history`, `can_stream_events`, `can_send_message`, `can_interrupt`, `can_steer`, `can_request_approvals`, `can_change_model`.
    - `SessionStatus`: `active`, `idle`, `interrupted`, `error`, `closed`, `locked_elsewhere`.
    - `NormalizedItem`: Tagged enum with variants `Message`, `Reasoning`, `ToolCall`, `ToolResult`, `FileChange`, `CommandExecution`, `ApprovalRequest`, `ApprovalResponse`, `TokenUsageItem`, `SystemNotice`.
    - `NormalizedTurn`: Turn identifier, session reference, ordinal sequence, status (`pending`, `running`, `completed`, `interrupted`, `failed`), and ordered list of `NormalizedItem`s.
    - `SessionHistoryQuery` and `SessionHistoryPage`: Cursor-based pagination supporting `Forward` and `Backward` traversals.
    - `SessionStreamEvent`: Real-time lifecycle events.
  - Define `AgentAdapter` asynchronous trait in `shardrail-session-core`:
    - `capabilities() -> AdapterCapabilities`
    - `list_sessions(&SessionListFilter) -> Result<Vec<SessionSummary>, AdapterError>`
    - `read_history(&SessionHistoryQuery) -> Result<SessionHistoryPage, AdapterError>`
    - `subscribe(&str) -> Result<broadcast::Receiver<SessionStreamEvent>, AdapterError>`
    - `send_message(&str, &str) -> Result<String, AdapterError>`
    - `interrupt(&str, Option<&str>) -> Result<(), AdapterError>`
    - `resolve_approval(&str, Uuid, ApprovalDecision) -> Result<(), AdapterError>`
    - `session_state(&str) -> Result<SessionStatus, AdapterError>`
  - Implement `FakeAgentAdapter` in `shardrail-session-core` with configurable capabilities, event broadcasting, and state tracking.
  - Add comprehensive contract test suite in `crates/session-core/tests/adapter_contracts.rs`.
  - Re-export normalized types in `@shardrail/client`.
- **Acceptance Criteria**:
  - [x] Design covers session listing, paged history, event streaming, sending, interruption, approvals, session state, capability flags.
  - [x] Normalized message/event model sufficient for both Codex and Claude Code; extensible for future agents.
  - [x] Contract tests pass against `FakeAgentAdapter`.
  - [x] Contracts live in Core (`Rust -> JSON Schema -> TypeScript`), and `./scripts/check-schema-drift.sh` is green.
  - [x] Interface approved with no Codex-specific or Claude-specific leakage into the shared layer.
