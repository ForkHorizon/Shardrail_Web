## 1. Research & Context
- **Stress Vectors Tested**:
  1. **Simultaneous Writers**: CLI agent, Shardrail web client, and Desktop app interacting with the same session file concurrently.
  2. **Rapid Message Bursts**: High-frequency token streaming and event deltas (>1,000 events/sec) injected into daemon and relay.
  3. **Very Long Sessions**: Sessions exceeding 10,000+ turns and >50,000 events.
  4. **Reconnect Storms**: Multiple browser clients (5–10 concurrent tabs) connecting, disconnecting, and reconnecting simultaneously while an agent turn is actively executing.
- **Reference Policies**:
  - `T3.4 Concurrent Writer Policy` (Codex advisory lock detection and read-only fallback).
  - `T4.7 Concurrent Writer Policy` (Claude PID descriptor detection and takeover rules).
  - `04 Architecture §2` (Daemon coalescing and per-client queue caps).

## 2. Concurrency Architecture & Guarantees
- **Single-Writer Advisory Protection**:
  - For Codex: `flock(fd, LOCK_EX | LOCK_NB)` detects active external CLI or app processes. If locked, Shardrail operates in read-only live sync mode, indicating "Active external writer" in the UI.
  - For Claude: Process table PID inspection and socket existence checks identify active writers.
- **Journal Monotonicity**:
  - Every committed journal row has an atomic integer `cursor: i64`. Cursors are strictly monotonic.
  - Any replayed event with `cursor <= last_acknowledged_cursor` is immediately deduplicated.
- **UI Store Coalescing**:
  - React store coalesces streaming token deltas into a single active message per frame interval (16.67ms), preventing unbounded virtual DOM re-renders and quadratic Markdown re-parsing.
