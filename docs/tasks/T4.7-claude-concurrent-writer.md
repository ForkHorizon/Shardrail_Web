## 1. Research & Context
- Claude Code registers active sessions in `~/.claude/sessions/<pid>.json` containing `sessionId`, `pid`, `cwd`, and timestamp metadata.
- When an interactive session process is killed or crashes, the PID file can become stale.
- Shardrail must verify PID liveness using POSIX signal 0 (`kill(pid, 0)`) via `nix::sys::signal::kill`.
- Stale session files whose PID is no longer running are recognized as unlocked.

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - Implement `is_session_locked`, `is_pid_alive`, `find_active_descriptor_by_session_id`, and `read_peer_token` in `crates/session-core/src/claude/lock.rs`.
  - Filter locked vs idle sessions accurately during session discovery.
- **Acceptance Criteria**:
  - [x] Accurate lock detection: returns `true` only if the PID file exists AND the process is actively alive.
  - [x] Stale lock resilience: dead PIDs are detected and treated as unlocked.
  - [x] Conformance with Shardrail concurrent-writer policy (T3.4).

## 3. Implementation Summary
