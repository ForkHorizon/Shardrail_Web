## 1. Research & Context
- **Official Documentation**: `Shardrail_Web/PLAN.md` (§7 Security & Trust Model, Phase 2 T2.6), React Aria accessibility guidelines, DOMPurify sanitization.
- **Established Facts**:
  - Information hierarchy: Machines → Agents → Sessions → Messages/Turns.
  - All outputs originating from agents (LLM reasoning, command execution stdout/stderr, diffs, tool calls) represent untrusted input that must be rendered safely to prevent cross-site scripting (XSS), prototype pollution, or CSS injection.
  - Safe mode rendering requirements:
    - Code diffs: Parse unified diff headers, hunks, additions, deletions, and context lines without raw HTML injection (`dangerouslySetInnerHTML`).
    - Command output: Preformatted view showing current working directory, command string, exit code badge, and stdout/stderr with copy-to-clipboard functionality.
    - Model reasoning/thought: Collapsible accordion tagged with untrusted indicator and execution duration.
    - Tool calls: Collapsible viewer displaying tool name, call ID, JSON arguments, and execution output safely.
  - Filtering and Search: Filter sessions by query (ID or title) and lifecycle status ('all', 'in-progress', 'completed'), and sort by newest/oldest/name.
  - Multi-viewport accessibility: Fully responsive on desktop and mobile viewports (e.g., iPhone 12/13/14 390x844), meeting WCAG 2.1 AA accessibility standards (audited via AxeBuilder).

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - UI Components:

    - `HierarchyNav`: Breadcrumb navigation bar across Machines → Agents → Sessions with dropdown selectors and agent filters.

    - Wire `SessionFilterBar` into `EntryArea.tsx` with live memoized filtering and empty state handling.
