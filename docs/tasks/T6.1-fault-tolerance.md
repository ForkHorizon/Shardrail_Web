## 1. Research & Context
- **Official Documentation**:
  - Shardrail Reliability Plan (`Shardrail_Web/PLAN.md`) §Stage 6.
  - Journal Specification and Failure Recovery Architecture (`Shardrail_Core/crates/journal/src/lib.rs`).
  - Relay Reconnect & Tunnel Architecture (`Shardrail_Web/crates/relay/tests/relay_integration.rs`).
- **Target Failure Scenarios**:
  1. Daemon restart in the middle of a turn.
  2. Relay restart while sessions are active.
  3. Machine reboot / abrupt host power termination.
  4. Browser tab closed / re-opened mid-execution.
  5. Network change / IP migration / interface flap.
  6. Disk full (`ENOSPC` / `SQLITE_FULL`) on daemon host.
  7. Clock skew / NTP step change during session turns.
- **Invariants Under Test**:
  - **Journal Intact**: SQLite WAL journal cannot be corrupted; schema integrity passes `PRAGMA integrity_check`.
  - **No Loss / No Duplication**: Event delivery uses monotonic cursors; reconnects resume from exact last acknowledged cursor.
  - **Honest Status**: If a turn was interrupted by crash, it is displayed as `interrupted` or `unconfirmed`, never `completed`.
  - **Fail-Closed Approvals**: Unresolved approval requests never auto-grant; on recovery, they withdraw or require explicit reconfirmation.
