## 1. Research & Context
- **Official Documentation & T2.1 Findings**:
  - Codex uses POSIX file locks via `flock(fd, LOCK_EX)` on lock files stored at `~/.codex/thread-writer-locks/{thread_id}.lock` (or `$CODEX_HOME/thread-writer-locks/{thread_id}.lock`).
  - When two writers access the same session simultaneously (e.g., Codex CLI and Shardrail daemon, or two CLI instances), simultaneous writes without coordination corrupt and interleave JSONL rollout records (`~/.codex/sessions/.../rollout-*.jsonl`).
  - Posix `flock` provides nonblocking exclusivity (`LOCK_NB`). The process holding the lock can be identified on macOS/Linux via file inspection (`lsof -t <lock_file_path>`).
- **Owner Approved Policy**:
  - Lock indicator + warning: If a session is active in another writer, reject write/resume commands with `"session is active elsewhere"`.
  - Graceful "Take Over" mode: Provide user confirmation in the UI; upon confirmation, issue `session.resume` with `take_over: true`, terminate the holding writer process gracefully with `SIGTERM` (falling back to `SIGKILL` if unreleased after timeout), release the lock, and resume the session in Shardrail.

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - `Shardrail_Core/crates/session-core/src/codex/lock.rs`:
    - Added `find_lock_holder_pid(locks_dir, thread_id)` using `lsof -t` to resolve the PID holding the `flock`.
    - Added `terminate_thread_lock_holder(locks_dir, thread_id, timeout_ms)`: issues `SIGTERM`, polls with exponential backoff up to `timeout_ms` (2000ms), and sends `SIGKILL` if still locked.
  - `Shardrail_Core/crates/shardraild/src/main.rs`:
    - `codex_thread_locks_dir()`: resolves `$CODEX_HOME/thread-writer-locks` or `~/.codex/thread-writer-locks`.
    - `resume_codex_session(daemon, session_id, take_over)`: checks lock state. If locked and `take_over == false`, rejects with `"session is active elsewhere"`. If `take_over == true`, terminates the lock holder and acquires the thread.
  - `Shardrail_Core/crates/shardraild/src/codex_app_server.rs`:
    - In `handle_turn_command`: if a session is not running in the daemon and its thread lock is held externally, rejects the command with `"session is active elsewhere"`.
  - `Shardrail_Web/apps/web/src/screens/session/SessionArea.tsx`:
    - Displays active elsewhere inline warning and a "Take Over Session" button.
    - Confirmation prompt: "Terminate other writer and resume here?" with "Confirm Take Over" and "Cancel" buttons using React Aria components.
  - `Shardrail_Web/apps/web/src/MainScreen.tsx` & `main.tsx`:
    - Dispatches `session.resume` with `{ session_id, take_over: true }`.
- **Acceptance Criteria**:
  - [x] Lock detection: identify whether a session has an active writer outside Shardrail.
  - [x] Warning indicator: return `"session is active elsewhere"` on write/resume attempts without take over.
  - [x] Take over mode: gracefully terminate the previous writer with confirmation and resume session cleanly.
  - [x] Automated integration tests verifying conflict scenarios (rejection when locked, clean takeover and resumption).
