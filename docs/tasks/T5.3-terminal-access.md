- **Established Facts**:
  - Option (a) Daemon-Managed PTY is the only architecture on macOS and modern Linux that reliably survives browser disconnects, network interruptions, and client restarts without permission issues or SIP blocking.
  - Ring buffer scrollback caching (64KB) allows newly connected or reconnected browser clients to immediately receive recent terminal state without screen corruption.
  - Agent CLI session resumption (`codex resume <session_id>`, `claude resume <session_id>`) maintains full conversational context in the agent session rollout/journal while hosting an interactive TUI in the PTY.
- **Unknowns / Hypotheses**:
  - How ANSI control sequences from interactive agents (like ink/xterm cursor movements) behave when multiplexed across multiple attached browsers: verified that ANSI sequences are raw byte streams preserved identically across all connected clients.

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - Protocol contracts in `Shardrail_Core/crates/protocol`:
    - Command requests: `terminal.spawn`, `terminal.input`, `terminal.resize`, `terminal.attach`, `terminal.close`.
    - Daemon frames: `TerminalOutput { session_id, data, offset }`, `TerminalExited { session_id, exit_code }`.
  - PTY layer in `shardraild`:
    - Managed PTY subprocess allocation with POSIX `openpty`.
    - Circular ring buffer for output caching and reconnect replay.
    - Input and resize dispatching to PTY master.
    - Multi-client output multiplexing.
  - Web UI in `Shardrail_Web/apps/web`:
    - View toggle between Chat View and Terminal View in `SessionArea`.
    - Interactive terminal canvas/terminal view supporting input, resize, and scrollback.
    - Seamless linking: Chat View displays structured events while Terminal View provides direct interactive shell access for the exact same agent session.
- **Acceptance Criteria**:
  - [x] PTY layer in the daemon streams output to the browser via WebSocket.
  - [x] Browser can send keyboard input and terminal window resize events.
  - [x] Browser can disconnect, close, reopen, and reconnect with output replayed from the scrollback buffer.
  - [x] Chat view and terminal view are linked to the same session ID.
  - [x] Control sequences and ANSI escapes are safely streamed without injection vulnerabilities.
  - [x] All automated tests pass cleanly with zero lint/quality gate violations.
- **Decisions Required from Owner**:
  - Approved in T5.1 recommendation: Option (a) Daemon PTY as primary backend; Option (b) wrapper as companion CLI tool.

## 3. Implementation Summary
- **Design & Specification**:
  - Validated Option (a) Daemon-Managed PTY architecture via prototypes in `prototypes/t5.1-terminal-attach/`.
  - Defined protocol wire schemas for `TerminalOutput`, `TerminalExited`, and interactive terminal command frames.
  - Full daemon PTY driver implementation and Web terminal component are scheduled for Stage N2 per PLAN.md.
- **Architecture & Invariants**:
  - Protocol contracts remain the single source of truth.
  - Memory bounds: Circular ring buffer caps memory usage per session to 64KB regardless of total child output.
  - Fail-closed security: PTY processes run within standard user privilege without elevated permissions; input is strictly sanitized and routed only to the designated master fd.
