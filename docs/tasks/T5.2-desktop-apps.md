## 1. Research & Context

### 1.1 Objective & Scope
The purpose of Task T5.2 is to investigate the architectural integration feasibility for GUI-based desktop AI coding agents within Shardrail. Specifically:
1. **OpenAI ChatGPT Desktop / Codex App** (`/Applications/ChatGPT.app`)
2. **Anthropic Claude Desktop** (`/Applications/Claude.app`)
3. **Google Antigravity** (`/Applications/Antigravity.app`)

For each application, the research investigates:
- Filesystem location and layout of session transcripts and persistent state.
- Storage coupling: whether the desktop GUI shares backing storage with its companion CLI.
- IPC interfaces: existence of local Unix domain sockets, named pipes, HTTP/WebSocket servers, or DevTools protocols.
- Programmatic message injection: feasibility of sending prompts without user intervention.
- External change reactivity: how the GUI responds when session files are appended or modified externally.
- Official interfaces vs. Accessibility UI automation: reliability, failure modes, security boundaries, and acceptable integration thresholds.

## 2. Technical Findings per Desktop Application

### 2.1 OpenAI Codex / ChatGPT Desktop App

#### Filesystem Layout & Storage Coupling
- **Application Bundle**: `/Applications/ChatGPT.app` (macOS native SwiftUI + Electron helper).
- **Bundled Engine**: Bundles the official Codex CLI directly within the application package at:
  `/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`
- **Storage Location**:
  - `~/.codex/sessions/rollups/<session_id>.jsonl`
  - `~/.codex/sessions/cache/`
  - `~/.codex/thread-writer-locks/`
- **Storage Sharing with CLI**: **100% Shared**. The ChatGPT desktop app and the standalone `codex` command-line tool use the exact same directory structure and append-only JSONL format in `~/.codex/`.

#### Local API & IPC Mechanisms
- **Unix Domain Sockets**: The application maintains a socket directory at `~/.codex/ipc/` (`ipc.sock`).
- **File Locks**: Active sessions maintain lockfiles in `~/.codex/thread-writer-locks/<session_id>.lock` to prevent conflicting write operations.
- **CLI Subprocess Interface**: The bundled `codex` binary supports non-interactive execution and headless resumption via `codex resume <session_id>`.

#### Reactivity to External File Modifications
- The desktop app uses native macOS file system event streaming (`FSEvents`) on `~/.codex/sessions/`.
- When an external process (such as Shardrail or the CLI) appends a new turn or message to the active session rollup JSONL file, the desktop GUI automatically re-renders the conversation thread without requiring an application restart.

#### Programmatic Message Sending
- **Official Interface**: Launching or resuming the session via the companion CLI binary (`codex exec` or `codex resume <id>`).
- **UI Automation (Accessibility)**: Possible via macOS Accessibility API (`AXUIElementCopyAttributeValue`, `AXUIElementPerformAction`), but requires explicit macOS Accessibility permissions in System Settings -> Privacy & Security, steals window focus, and breaks if the UI layout shifts.

### 2.2 Anthropic Claude Desktop (`Claude.app`)

#### Filesystem Layout & Storage Coupling
- **Application Bundle**: `/Applications/Claude.app` (Electron-based application).
- **Embedded Engine**: Includes an embedded Claude Code engine under:
  `~/Library/Application Support/Claude/claude-code/<version>/<hash>/claude.app`
- **Storage Location**:
  - General chat sessions: Encrypted LevelDB / IndexedDB in `~/Library/Application Support/Claude/`.
  - Claude Code developer sessions: `~/.claude/projects/<project_slug>/<session_id>.jsonl`.
- **Storage Sharing with CLI**: **Partial / Bifurcated**.
  - Direct web-synced personal chats in Claude Desktop do not write to local JSONL files.
  - Claude Code developer projects configured within Claude Desktop write directly to the standard `~/.claude/projects/` tree and are completely shared with the `claude` CLI.

#### Local API & IPC Mechanisms
- **Unix Domain Sockets**: Active Claude Code sessions spawn local sockets referenced in `~/.claude/sessions/<pid>.json`, protected by a companion `.key` peerToken authentication file.
- **Public API**: Claude Desktop exposes no open local HTTP/WebSocket endpoint for third-party message dispatch.

#### Reactivity to External File Modifications
- For Claude Code sessions in `~/.claude/projects/`, external appends to the active JSONL file are safely detected by the underlying runtime upon turn completion.
- However, if the desktop GUI is actively in the middle of generating a streaming token response, external writes to the same session file trigger lock collisions.

#### Programmatic Message Sending
- **Official Interface**: The supported and robust integration vector is the Claude Code CLI (`claude --resume <session_id>`) via the Shardrail daemon PTY layer.
- **UI Automation (Accessibility)**: Can target the Electron window to paste text into the prompt textarea and simulate `Enter`.
  - *Risk*: High. Accessibility focus theft interrupts active user typing; Electron DOM updates frequently break accessibility element trees.

### 2.3 Google Antigravity (`Antigravity.app`)
The official [hooks documentation](https://antigravity.google/docs/hooks?authuser=3) provides a transcript path through `transcriptPath`, under `~/.gemini/antigravity/brain/<conversationId>/.system_generated/logs/transcript.jsonl`. It does not specify the JSONL record schema, transcript write/flush guarantees, or a supported resume command. The previously recorded internal SQLite paths, tables, and WAL claims were unverified and are withdrawn. Antigravity read, live sync, and write support are deferred.

## 4. Official Interfaces vs. Accessibility UI Automation

### 4.1 Accessibility UI Automation Breakdown
Automating desktop applications via macOS Accessibility (`AXUIElement`) or Linux AT-SPI presents severe architectural flaws:
1. **OS Permission Fragility**: Requires the user to manually authorize Shardrail in system privacy settings. Permissions reset on binary updates.
2. **Focus Stealing & Window Management**: Driving the GUI requires focusing the target window. If the user is typing in another application, focus shifts abruptly, causing lost keystrokes and severe UX disruption.
3. **Selector Instability**: Electron and SwiftUI element hierarchies change between minor version updates, causing sudden script failures.
4. **Zero Headless / Remote Viability**: Accessibility automation is impossible over SSH or in headless server environments.

### 4.2 Proposed Acceptable Integration Boundary
Shardrail establishes a strict, professional integration boundary across all desktop apps:
1. **Zero UI Hacks**: No macOS Accessibility keystroke injection, no synthetic mouse clicks, no window focus manipulation.
2. **Storage-Level Telemetry (Read & Live Sync)**:
   - Tail append-only JSONL files (`.codex`, `.claude`).
   - Antigravity parsing is deferred; the documented transcript path has no published record schema.
3. **Daemon PTY Execution (Write & Launch)**:
   - Resume the selected local Codex or Claude Code session through its CLI inside a Shardrail-managed PTY.
   - GUI session sharing is not inferred unless the provider documents that behavior.
