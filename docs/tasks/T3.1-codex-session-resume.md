## 1. Research & Analysis [R]

### 1.1 Resume Method Selection: `app-server` vs CLI
- **Evaluation**:
  - `codex app-server` exposes the JSON-RPC method `thread/resume` (`params: { "threadId": "<uuid>" }`).
  - `codex exec resume <thread_id> <prompt>` executes a single turn over the CLI and exits.
- **Decision**: Select `codex app-server` via `thread/resume`.
  - *Persistent stdio & JSON-RPC*: Maintains bidirectional connection for streaming items (`turn/start`, `item/agentMessage/delta`, `item/commandExecution/outputDelta`, `turn/completed`).
  - *Approval routing*: Live interactive approval notifications (`item/commandExecution/requestApproval`, `item/fileChange/requestApproval`) are delivered to Shardrail and resolved without process restarts.
  - *Architecture alignment*: Directly fits the existing `shardraild` session runner (`codex_app_server.rs`) without managing ephemeral CLI wrapper processes.

### 1.2 State Preservation Matrix: What is Preserved vs Lost
| State Dimension | Preserved on Resume? | Notes |
|---|---|---|
| Conversation History | **Yes** | Full transcript: user prompts, agent thoughts, assistant responses, and tool calls are reloaded by Codex. |
| Model Context Window | **Yes** | Previous turn tokens and instructions are preserved by Codex. |
| Session Rollout File | **Yes** | Located at `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`. New turns append append-only lines; prior entries are not mutated. |
| Thread UUID | **Yes** | The session thread identifier remains stable across turns and tools. |
| In-flight Subshell PTYs | **No (Lost)** | Any background process spawned by bash/exec in a prior turn terminates with process group exit. |
| In-flight Approvals | **No (Lost)** | Any uncommitted approval request pending at disconnect is marked abandoned/withdrawn fail-closed. |
| Ephemeral Turn State | **No (Lost)** | Active turns interrupted mid-generation do not resume partially; a new `turn/start` must be dispatched. |

### 1.3 Transitioning from Ephemeral to Persisted Sessions
- In testing/fake mode, `ephemeral: true` is passed to prevent rollout file clutter.
- For standard production and resumed sessions, `ephemeral: false` is configured.
- Clean separation:
  - CLI argument `--codex-ephemeral` allows explicitly requesting ephemeral test mode.
  - Command requests (`session.create`) can specify `"ephemeral": true` or default to persistent (`ephemeral: false`).
  - Daemon startup and resume commands verify rollout path presence and allowlist compliance.

### 1.4 Effect on the Session Rollout File
- Live verification confirmed: Codex does *not* rewrite, truncate, or re-index the JSONL file on resume.
- It writes an append-only stream of `turn/start`, `item/*`, and `turn/completed` events into the existing file.
- Checksums and byte offsets remain monotonically increasing, allowing live sync engines to continue watching without re-parsing history.

## 2. Design & Implementation [D]

### 2.1 Protocol and Daemon Dispatch
- Implemented `session.resume` in `shardraild` command loop:
  - Validates client authorization (rejects `ClientScope::Limited`).
  - Parses target `session_id` (UUID format validation).
  - Resolves workdir from journal or discovers rollout file via `parse_rollout_file`.
  - Re-opens or verifies session coordinator and journal entries.
  - Starts or reconnects worker actor with `resume_thread_id: Some(session_id)`.

### 2.2 Codex App-Server Subprocess Wiring
- `crates/shardraild/src/codex_app_server.rs`:
  - Added `resume_thread_id: Option<String>` and `ephemeral: bool` to `CodexConfig` and `CodexRun`.
  - Added `PendingRpc::ThreadResume` RPC response handler.
  - Updated `CodexRun::run`: if `resume_thread_id` is set, issues `thread/resume` with `{"threadId": id}` instead of `thread/start`.
  - Updated `thread_routing_accepted`: relaxes `path: null` check when `ephemeral: false` to accept persistent session rollouts.
  - Updated `thread/started` notification guard to enforce ephemeral check only when `ephemeral: true`.

### 2.3 Fake Server Fixture for CI
- Updated `crates/shardraild/tests/fixtures/fake_codex_app_server.py`:
  - Added `thread/resume` RPC handler returning simulated session data for requested `threadId`.

## 4. Invariants & Security
- **Fail-Closed Permissions**: `session.resume` requires full client scope; limited/observer clients are rejected immediately.
- **Workdir Allowlisting**: Resumed sessions must resolve to a directory within the allowlisted session workdirs; path traversal or unlisted workdirs fail closed.
- **Auditing**: Session continuation transitions (`process_started` with `resumed: true`) are committed to the append-only journal before provider interaction.
