# T5.4: Desktop Session Access

- **Status:** Partial
- **Repositories:** `Shardrail_Core` and `Shardrail_Web`

## Support

| Provider history | Read | Live sync | Continue | Limits |
|---|---|---|---|---|
| Codex local sessions | Implemented | Implemented | Managed `codex resume <id>` terminal | GUI-only sessions not present in local history are unavailable. |
| Claude Code local sessions | Implemented | Implemented | Managed `claude --resume <id>` terminal | Claude Desktop cloud chats are unavailable. |
| Antigravity | Deferred | Deferred | Deferred | Official hooks expose a transcript path but do not document its JSONL record schema. Internal SQLite parsing is not supported. |

Codex and Claude Code session history uses the existing JSONL discovery and live-sync engines in Core. Web loads history for the selected discovered session, subscribes to its stream, and merges item updates by provider item ID. Partial final JSONL records remain unread until completed, so a writer can safely finish the record.

Terminal resume requires a full client or an explicitly enrolled limited browser (`shardraild client enroll-terminal --label browser`). The daemon also checks provider session locks. Shardrail does not automate GUI windows or modify provider history files.

Antigravity's [official hooks documentation](https://antigravity.google/docs/hooks?authuser=3) identifies `transcriptPath` under `~/.gemini/antigravity/brain/<conversationId>/.system_generated/logs/transcript.jsonl`; record semantics are not documented. Add support only after a documented format or a separately approved hook integration exists.
