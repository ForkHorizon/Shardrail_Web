## 1. Research & Context
- **Official Documentation**: Codex CLI documentation, `codex app-server` experimental RPC contracts, and empirical research documented in `T2.1-codex-research.md`.
- **Agent / Tooling Versions**: Codex CLI `0.166.0` (with multi-version compatibility verified across legacy sessions from `0.14.0`, `0.18.0`, and `0.166.0`), Rust 1.86 / 1.99 nightlies, SQLite 3.x.
- **Established Facts**:
  - `~/.codex/state_5.sqlite` provides the primary index of all threads created across CLI and GUI surfaces (`source`: `cli`, `exec`, `vscode`, `appServer`).
  - Active sessions lock advisory writer locks at `~/.codex/thread-writer-locks/<uuid>.lock`. On macOS/Unix systems, opening the lock file in read-only mode (`O_RDONLY`) and testing `flock(LOCK_EX | LOCK_NB)` non-destructively detects locked sessions (`EWOULDBLOCK` / `EAGAIN`) without requiring write access or altering lock state.
  - Fallback parsing paths (`session_index.jsonl` and directory traversal of `~/.codex/sessions/**/rollout-*.jsonl`) guarantee session discovery when SQLite databases are absent, busy, or corrupted.
- **Unknowns / Hypotheses**:
  - Verified: Non-blocking flock detection reliably distinguishes `SessionStatus::LockedElsewhere` vs `SessionStatus::Idle` without disturbing concurrent processes.
  - Verified: Filename heuristic sliding window recovers valid session IDs and timestamps even on corrupted, truncated, or 0-byte rollout files.
