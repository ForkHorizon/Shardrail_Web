## 1. Research & Context
- **Official Documentation**: Codex app-server JSON-RPC interface (`turn/start`, `turn/interrupt`, `item/*`, `turn/completed`).
- **Installed Codex Version**: Codex `0.166.0`.
- **Established Facts**:
  - `turn.start` dispatches prompts to active sessions when idle.
  - Sending prompt commands while a turn is active (`Running`, `Stalled`, `Cancelling`) must not drop user input or cause racing turn state.
  - Coordinator models `QueueState` (`Empty`, `Queued(prompt)`, `Dispatching(prompt)`).
  - Codex `turn/interrupt` terminates generation; when interrupted, any queued prompt is retained rather than automatically executed.
  - Idempotency by `command_id` must be preserved after connection drops or retransmissions.

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - Coordinator: add `instruction_queued` transition and reset `session.queue` to `Empty` on `turn_started`.
  - Daemon socket routing: support `instruction.queue` and auto-queue `turn.start` when sent during an active turn.
  - Codex app-server adapter: dispatch queued instructions automatically when a turn completes normally with outcome `Provider`.
  - Idempotency: replay of turn and interrupt commands returns existing event IDs and does not duplicate actions.
- **Acceptance Criteria**:
  - [x] Send prompt to a session starts turn and streams items (`turn_started`, deltas, `turn_finished`).
  - [x] Instruction queueing: prompt submitted during active turn transitions queue state to `Queued`.
  - [x] Auto-advance: upon successful completion (`TurnOutcome::Provider`), queued prompt automatically transitions and begins a new turn.
  - [x] Interrupt: `turn.interrupt` sends `turn/interrupt` to Codex, marks turn `Interrupted`, and holds any queued prompt without auto-advancing.
  - [x] Idempotency: replaying `turn.start` or `turn.interrupt` with identical `command_id` succeeds idempotently without re-triggering.
