## 1. Security Scope & Threat Model
- **Threat Boundary**:
  - Outbound E2E-encrypted tunnel from `shardraild` to Relay.
  - Browser clients connecting to Relay and terminating E2E tunnel to Daemon.
  - Local workstation filesystem and agent child processes (Codex, Claude, Antigravity).
- **Core Security Principles**:
  1. **Relay Compromise Assumption**: The relay server is untrusted (honest-but-curious or fully compromised). The relay must NEVER have access to plaintext session content, agent outputs, commands, or approval secrets.
  2. **Fail-Closed Permissions**: Approvals and containment permissions default to deny.
  3. **Untrusted Agent Output**: Model text, tool responses, diffs, and terminal escapes are strictly treated as hostile untrusted inputs.
  4. **Zero Secrets in Storage/Logs**: Redaction filters strip API keys, bearer tokens, passwords, and private keys before journal persistence.

## 3. Findings & Remediations
- **Finding 1 (Low, Remediated)**: Journal files on POSIX filesystems must never inherit permissive umask.
  - *Remediation*: Explicitly set `0o600` permissions on journal creation (`journal_file_is_created_private_and_existing_files_are_hardened`).
- **Finding 2 (Informational, Accepted Risk)**: Stored Git workspace paths may expose local username structure in metadata.
  - *Accepted Risk*: Required for UI workspace path display; internal to authenticated and paired client sessions.
