## 1. Context & Research Finding
In Task T4.1 (`docs/tasks/T4.1-claude-research.md`), we conducted an empirical audit of Claude Code session formats (`~/.claude/projects/<slug>/<sessionId>.jsonl`), subagent sidechains, process tracking (`~/.claude/sessions/<pid>.json`), IPC sockets (`/tmp/cc-socks/<pid>.sock`), and the Agent SDK (`@anthropic-ai/claude-agent-sdk`).

We evaluated Claude Code against the unified `AgentAdapter` interface designed in Task T2.2 (`crates/session-core/src/adapter.rs` and `crates/protocol/src/lib.rs`).

---

## 2. Decision & Compatibility Evaluation

| Interface Feature / Method | T2.2 Design | Claude Code Alignment | Required Interface Change? |
|---|---|---|---|
| **`capabilities()`** | `AdapterCapabilities` struct with boolean capability flags | Reports `can_list_sessions: true`, `can_read_history: true`, `can_stream_events: true`, `can_send_message: true`, `can_interrupt: true`, `can_steer: false`, `can_request_approvals: true`, `can_change_model: false`. | **None**. Capability flags cleanly convey Claude's behavior without vendor leakage. |
| **`list_sessions()`** | `SessionListFilter -> Vec<SessionSummary>` | Reads `~/.claude/projects/` directory or SDK `listSessions()`. Maps `sessionId`, `cwd`, `lastModified`, `summary`. | **None**. Fully compatible. |
| **`read_history()`** | `SessionHistoryQuery -> SessionHistoryPage` | Traverses `<sessionId>.jsonl`. Maps `user`/`assistant` records to `NormalizedTurn` containing `NormalizedItem::Message`, `Reasoning` (`thinking`), and `ToolCall` (`tool_use`). | **None**. Fully compatible. |
| **`subscribe()`** | Live `SessionStreamEvent` broadcast receiver | Tails `.jsonl` for passive sessions; parses `stream-json` stdout for active sessions. | **None**. Fully compatible. |
| **`send_message()`** | `(session_id, prompt) -> turn_id` | Spawns `claude -p stream-json --resume <session_id>` or routes via UDS socket if active in CLI. | **None**. Fully compatible. |
| **`interrupt()`** | `(session_id, Option<turn_id>)` | Sends `SIGINT` to child process. | **None**. Fully compatible. |
| **`resolve_approval()`** | `(session_id, approval_id, decision)` | Translates to stdio `control_response` (`behavior: "allow"` / `"deny"`). | **None**. Fully compatible. |
| **`session_state()`** | `session_id -> SessionStatus` | Evaluates PID file in `~/.claude/sessions/<pid>.json`. | **None**. Fully compatible. |

---

## 3. Decision Conclusion
**No breaking or additive changes are required to the T2.2 interface.**
The generic model in `shardrail-protocol` and `shardrail-session-core` successfully accommodates both OpenAI Codex and Anthropic Claude Code without vendor-specific branching or leakage in the core protocol.
