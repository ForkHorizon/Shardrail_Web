## 1. Research & Context
- Claude Code writes incremental transcript records to `~/.claude/projects/<slug>/<id>.jsonl` as turns execute.
- Turn boundaries are marked by `stop_reason` (`end_turn`, `tool_use`, `max_tokens`) within assistant messages.
- Active sessions require file-watching and monotonic byte-offset tailing without duplicate event dispatch.

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - Implement `ClaudeLiveSyncEngine` in `crates/session-core/src/claude/live.rs` with byte-offset tracking, deduplication of parsed items, and event streaming.
  - Implement `ClaudeLiveWatcherHandle` and `start_claude_live_watcher` integrating `notify::RecommendedWatcher` with fallback periodic polling.
- **Acceptance Criteria**:
  - [x] Incremental real-time streaming: new JSONL records converted into `NormalizedItem` and `TurnCompleted` events.
  - [x] Deduplication: duplicate reads at turn boundaries are suppressed via stable item ID tracking.
  - [x] Turn boundary detection: recognizes `stop_reason` both at root and within nested `message` payloads.
  - [x] Resilience: survives file truncation (resets offset cleanly) and skips corrupt lines.

## 3. Implementation Summary
